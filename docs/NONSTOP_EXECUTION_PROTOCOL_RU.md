# Nonstop Execution Protocol (do-all)

## Цель

Сделать выполнение плана непрерывным: агент идет по очереди задач без промежуточных пауз и останавливается только по `STOP`/`PAUSE` или hard-blocker.

## Единый цикл выполнения

1. Взять следующий actionable пункт из `.cursor/memory/ACTIVE.md` (`## Открытые задачи`).
2. Сделать минимальный завершенный change-set по пункту.
3. Провести проверку (релевантные тесты, при необходимости smoke/runtime).
4. Обновить `.cursor/memory/ACTIVE.md`:
   - `## Сводка`,
   - `## Файлы сессии`,
   - `## Открытые задачи` (следующие 1-3 шага).
5. Немедленно перейти к следующему actionable пункту.

Промежуточные "готово, продолжать?" запрещены.

## Условия остановки

Допустимы только два типа остановки:

1. Явная команда пользователя: `STOP` или `PAUSE` (регистр не важен).
2. Hard-blocker.

## Что считается hard-blocker

- Нет необходимых секретов/доступов (API keys, credentials, права).
- Нужна необратимая операция и нет явного разрешения.
- Требуется продуктовый выбор между равнозначными вариантами, а требований недостаточно.

Все остальные ошибки считаются рабочими: агент делает retry/recovery и продолжает цикл.

## Fallback, если ACTIVE пустой

Если в `ACTIVE.md` нет actionable задач:

1. Взять следующий unchecked пункт из `PROJECT_TASK_PROMPT_RU.md`, раздел `Следующий спринт (5–7 дней, immediate)`.
2. Если раздел закрыт — взять ближайший unchecked пункт из `Трек 1..5`.
3. Если и там нет — взять unchecked пункт из `Фаза 5`.

После выбора:

- записать пункт в `ACTIVE.md -> ## Открытые задачи`,
- сразу перейти к выполнению по основному циклу.

## Команды управления

- `stop` / `STOP` — полная остановка цикла.
- `pause` / `PAUSE` — пауза; продолжение только после команды пользователя.
- Любой другой запрос трактуется как рабочий и исполняется без "done-паузы".
